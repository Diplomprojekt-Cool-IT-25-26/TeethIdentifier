# TeethIdentifier — Setup Guide

This guide covers what is not in the repository, why, and how to get the project running on a new machine.

---

## What is NOT committed (and why)

### 1. The dataset — `data/`

The 7 data folders (`data_part_1/` through `data_part_7/`) contain **1,850 3D dental scans** from the 3DTeethSeg MICCAI Challenge dataset. Each scan is a pair of files:

```
data/data_part_N/lower/PATIENT_ID/PATIENT_ID_lower.obj   ← 3D mesh
data/data_part_N/lower/PATIENT_ID/PATIENT_ID_lower.json  ← vertex labels
data/data_part_N/upper/PATIENT_ID/PATIENT_ID_upper.obj
data/data_part_N/upper/PATIENT_ID/PATIENT_ID_upper.json
```

Each `.obj` file is roughly 10–30 MB. Total dataset size: **~20–40 GB**. Git is not designed for binary files this large and GitHub has a 100 MB file limit.

**To get the data:** Download from the 3DTeethSeg challenge. See `docs/links that everyone should check out.txt` for the source. After downloading, put the patient folders under `data/data_part_1/lower/`, `data/data_part_1/upper/`, etc.

---

### 2. ML outputs — `ml_outputs/`

Everything under `ml_outputs/` is generated and large:

| Path | What it is | Why excluded |
|---|---|---|
| `ml_outputs/training_data/train.pkl` | ~200k training samples as NumPy arrays | 5–10 GB, generated by `generate_data.py` |
| `ml_outputs/training_data/val.pkl` | Validation split | 1–2 GB, generated by `generate_data.py` |
| `ml_outputs/training_data/test.pkl` | Test split | 1–2 GB, generated by `generate_data.py` |
| `ml_outputs/models/teeth_classifier.keras` | Trained model weights | ~100 MB, trained by `train.py` |
| `ml_outputs/models/checkpoints/` | Per-epoch model snapshots | Many GB combined |
| `ml_outputs/logs/` | TensorBoard event files | Large, regenerated on retrain |
| `ml_outputs/results/` | Prediction meshes, plots, JSON | Generated by `evaluate.py` / `visualize.py` |

Only `ml_outputs/.gitkeep` is committed to preserve the directory structure in git.

**To get the model:** Either train from scratch (see workflow below) or copy `teeth_classifier.keras` manually from the original machine.

---

### 3. The virtual environment — `venv/`

The `venv/` folder is **~2–4 GB** and entirely machine-specific (compiled C extensions, absolute paths baked in). It must be recreated on each machine.

**See "Setting up the virtual environment" below.**

---

### 4. Generated images — `*.png`, `*.jpg`

Plots, confusion matrices, prediction visualizations. All regenerated by running `evaluate.py` or `visualize.py`.

---

### 5. Logs and caches — `*.log`, `__pycache__/`, `*.pyc`

Transient files. Ignored to keep the repo clean.

## Setting up the virtual environment on a new machine

The project requires a **specific combination of Python, TensorFlow, PyTorch, and CUDA** due to Windows GPU compatibility constraints.

### Requirements

| Component | Version | Reason |
|---|---|---|
| Python | **3.10.11** | Last version with TensorFlow 2.9 native Windows GPU support |
| TensorFlow | **2.9.0** | Last TF with native Windows GPU (no WSL needed) |
| CUDA | **11.2** | Required by TF 2.9 on Windows |
| cuDNN | **8.1** | Required by TF 2.9 on Windows |
| PyTorch | **1.12.0+cu113** | GPU patch generation (V3 generator) |
| PyTorch3D | **0.7.2** | (optional, legacy GPU generator) |

> Do **not** update TensorFlow to 2.10+ — native Windows GPU was dropped. TF 2.10+ requires WSL2 on Windows.

### Step-by-step setup

```bash
# 1. Create venv with Python 3.10
py -3.10 -m venv venv

# 2. Activate
venv\Scripts\activate

# 3. Upgrade pip
python -m pip install --upgrade pip

# 4. Install dependencies
pip install -r requirements.txt
```

`requirements.txt` pins all versions. If PyTorch fails to install via pip (it needs the CUDA index), install it separately first:

```bash
pip install torch==1.12.0+cu113 torchvision==0.13.0+cu113 --extra-index-url https://download.pytorch.org/whl/cu113
pip install -r requirements.txt
```

### Verify the setup

```bash
python -c "import tensorflow as tf; print(tf.config.list_physical_devices('GPU'))"
python -c "import torch; print(torch.cuda.is_available())"
```

Both should show your GPU. If TensorFlow shows `[]`, check that CUDA 11.2 and cuDNN 8.1 are installed and on your `PATH`.

## How the project works

### Overview

TeethIdentifier classifies every vertex in a 3D dental mesh as either **tooth** (label 1) or **gingiva/gum** (label 0). It does this by:

1. Projecting a small neighborhood around each vertex onto a 100×100 RGB image patch
2. Running that patch through a CNN (TeethNet)
3. Optionally applying morphological post-processing to smooth the boundary

### Data pipeline

```
Raw .obj mesh + .json labels
        ↓
  DatasetSampler / GPUPatchGeneratorV3
  (project 3D surface neighborhood → 100×100 RGB patch)
        ↓
  train.pkl / val.pkl / test.pkl
  (balanced: ⅓ boundary vertices, ⅓ clear gingiva, ⅓ clear tooth)
        ↓
  TensorFlow Dataset (loaded by data_loader.py)
```

The patch generation step is the computational bottleneck. `GPUPatchGeneratorV3` (in `tools/gpu_patch_generator_v3.py`) uses a custom PyTorch GPU rasterizer that achieves ~18 patches/ms, making full-scan inference (~93k vertices) complete in about 20 seconds on an RTX 3070.

### Model — TeethNet

Defined in `src/model.py`. Standard CNN with batch normalization and dropout:

```
Input: 100×100×3
→ Conv2D(32) → BatchNorm → MaxPool → Dropout(0.25)
→ Conv2D(64) → BatchNorm → MaxPool → Dropout(0.25)
→ Conv2D(128) → BatchNorm → MaxPool → Dropout(0.3)
→ Flatten
→ Dense(256) → BatchNorm → Dropout(0.5)
→ Dense(64) → Dropout(0.4)
→ Dense(1, sigmoid)
```

Output: probability that the vertex is a tooth. Threshold: 0.5.

### Post-processing

After inference, `tools/mesh_morphology.py` applies morphological operations on the vertex adjacency graph to clean up predictions:

**Default (recommended) settings:**
- `open_iters=2` — opening on teeth: removes small isolated tooth islands in gingiva
- `close_iters=2` — closing on teeth: fills small gingiva gaps within tooth regions
- `erode_gingiva_iters=1` — erodes gingiva border slightly (corrects over-prediction)
- Connected component filter: removes any region < 500 vertices
- Boundary smoothing: 10 iterations of graph diffusion on the boundary

Optional (off by default):
- `--majority-vote N` — trims gingiva peninsulas
- `--open-gingiva N` — removes thin gingiva fingers
- `--reconstruct N` — morphological reconstruction to sever and remove fingers

## Complete workflow (from scratch)

All commands run from the project root with the venv activated.

```bash
venv\Scripts\activate
```

### Step 1 — Generate training data

```bash
python scripts/generate_data.py
```

Reads raw `.obj`/`.json` files from `data/`, generates patches, saves `ml_outputs/training_data/{train,val,test}.pkl`. Takes 2–4 hours for 400 scans.

Key settings in `config.yaml`: `scans_for_training` (default 400), `samples_per_scan` (default 500).

### Step 2 — Train the model

```bash
python src/train.py
```

Trains TeethNet on the `.pkl` files. Best model saved to `ml_outputs/models/teeth_classifier.keras`. Takes 8–12 hours on RTX 3070.

### Step 3 — (Optional) Continue training

```bash
python scripts/continue_training.py --epochs 30 --lr 0.00005
```

Resumes from the saved model with a lower learning rate. Useful if validation accuracy plateaued.

### Step 4 — Evaluate on the test set

```bash
python src/evaluate.py
```

Outputs accuracy, precision, recall, F1, ROC-AUC, confusion matrix, and per-patient analysis to `ml_outputs/results/`.

### Step 5 — Visualize predictions

```bash
# Default (recommended post-processing, first scan found)
python scripts/visualize.py

# Specific scan
python scripts/visualize.py --scan O52P1SZT

# Without post-processing (raw model output)
python scripts/visualize.py --no-postprocess

# Fast mode (sample 1/25 vertices, for quick checks)
python scripts/visualize.py --fast
```

Outputs to `ml_outputs/results/`:
- `prediction_mesh_<scan>.obj` — colored mesh (ivory=tooth, pink=gingiva)
- `prediction_data_<scan>.json` — per-vertex predictions and confidences
- `prediction_viz_<scan>.png` — 3D scatter plot screenshot

### Step 6 — Launch interactive dashboard

```bash
streamlit run app.py
```

Open `http://localhost:8501`. Shows dataset stats, model config, training curves, evaluation metrics, and an inference UI.

## Notes for the laptop setup

1. **Copy the trained model** from this machine to the laptop: `ml_outputs/models/teeth_classifier.keras`
2. **Recreate the venv** using the steps above — do not copy the `venv/` folder, it won't work on a different machine
3. **Get the dataset** — either copy from this machine or re-download from the source
4. The `config.yaml` paths use absolute Windows paths (`D:/All projects/TeethIdentifier/data`) — update them if the project lives in a different location on the laptop
5. Verify CUDA and cuDNN versions match before running (TF 2.9 requires CUDA 11.2 + cuDNN 8.1)
