# TeethIdentifier

Binary per-vertex classification of 3D dental scans: every vertex in an `.obj`
mesh gets labelled either **tooth** or **gingiva (gum)**.

---

## What's in the repo and what isn't

Large or machine-specific things are **not** committed. You need to produce or
download them before the pipeline will run.

### Not committed

| Path | What it is | How to get it |
|---|---|---|
| `data/` | 1,850 3D dental scans (`.obj` + `.json` label pairs), ~20–40 GB total | Download the 3DTeethSeg MICCAI Challenge dataset — link in `docs/links that everyone should check out.txt`. Drop the patient folders under `data/data_part_1/lower/`, `data/data_part_1/upper/`, etc. |
| `ml_outputs/training_data/*.pkl` | Generated patch datasets, 7–14 GB | Run `scripts/generate_data.py` |
| `ml_outputs/models/*.keras` | Trained CNN weights, ~100 MB | Either train with `src/train.py` or copy over from another machine |
| `ml_outputs/logs/` | TensorBoard events, checkpoints, plots | Regenerated automatically by training/evaluation |
| `venv/` | Python virtual environment, 2–4 GB | Recreate on each machine (see below — venvs have absolute paths baked in and don't move between machines) |
| `*.png`, `*.jpg` | Plots and visualisations | Regenerated by `evaluate.py` / `visualize.py` |

Only `ml_outputs/.gitkeep` is committed from `ml_outputs/` — enough to preserve
the folder for the paths in `config.yaml`.

### Committed

Everything you need to reproduce the pipeline: source code, scripts, tools,
configuration, and dependency pins.

## Setting up the environment

The stack is pinned to a specific Python/TensorFlow/CUDA combination because
that's the last version of TF with native Windows GPU support. Do not try to
bump TensorFlow to 2.10+ as it dropped native Windows GPU and requires WSL2.
With different hardware, this would allow for more compatible version
combinations to Cool IT's systems.

| Component | Version | Why |
|---|---|---|
| Python | 3.10.11 | Last version TF 2.9 supports |
| TensorFlow | 2.9.0 | Last TF with native Windows GPU |
| CUDA | 11.2 | Required by TF 2.9 on Windows |
| cuDNN | 8.1 | Required by TF 2.9 on Windows |
| PyTorch | 1.12.0+cu113 | Used by the GPU patch generator |

### Install

```bash
py -3.10 -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If pip fails to find the PyTorch CUDA wheel, install it separately first:

```bash
pip install torch==1.12.0+cu113 torchvision==0.13.0+cu113 \
    --extra-index-url https://download.pytorch.org/whl/cu113
pip install -r requirements.txt
```

### Verify

```bash
python -c "import tensorflow as tf; print(tf.config.list_physical_devices('GPU'))"
python -c "import torch; print(torch.cuda.is_available())"
```

Both should report your GPU. If TF reports `[]`, check that CUDA 11.2 and
cuDNN 8.1 are installed and on your `PATH`.

### On a new machine

1. Recreate the venv using the steps above. Do **not** copy `venv/` across
   machines, it won't work.
2. Either retrain or copy `ml_outputs/models/teeth_classifier.keras` over
   manually.
3. Copy or redownload the dataset into `data/`.
4. Check the paths in `config.yaml` — `paths.data_root` is an absolute Windows
   path and needs editing if the project lives somewhere different.

## How the pipeline works

```
  raw .obj mesh + .json labels
              │
              ▼
   patch generation           (tools/gpu_patch_generator_v3.py)
   — for every vertex, render a 100×100 image of its neighbourhood
              │
              ▼
   balanced sampling           (tools/dataset_sampler.py)
   — ⅓ boundary, ⅓ clear gingiva, ⅓ clear tooth
              │
              ▼
   train / val / test .pkl     (ml_outputs/training_data/)
              │
              ▼
   TeethNet CNN                (src/model.py)
   — 3 conv blocks → 2 dense → sigmoid
              │
              ▼
   per-vertex probability → threshold at 0.5
              │
              ▼
   morphological post-processing   (tools/mesh_morphology.py)
   — opening / closing / erosion / smoothing on the mesh graph
              │
              ▼
   coloured .obj + .json side-car
```

### Patches

Each patch is 100×100×3. The channels are **not** a camera photo, they're
geometric features projected onto the image plane:

- **R** = depth (distance from the virtual camera)
- **G** = shading (normal dot view direction)
- **B** = curvature (how sharply the surface bends at the point)

The rasterizer (`tools/gpu_patch_generator_v3.py`) uploads the mesh to GPU
once, then for each vertex projects the surrounding triangles into camera
space and rasterises them with barycentric sampling and a z-buffer. It runs
at about 18 patches/ms, which puts full-scan inference (~93k vertices) under
30 seconds on the hardware that was available to the project team.


### Model — TeethNet

```
Input: 100×100×3
  → Conv2D(32) → BatchNorm → MaxPool → Dropout(0.25)
  → Conv2D(64) → BatchNorm → MaxPool → Dropout(0.25)
  → Conv2D(128) → BatchNorm → MaxPool → Dropout(0.3)
  → Flatten
  → Dense(256) → BatchNorm → Dropout(0.5)
  → Dense(64) → Dropout(0.4)
  → Dense(1, sigmoid)
```

About 2.5M parameters, fits comfortably in 8 GB VRAM.

### Post-processing

The CNN classifies every vertex independently, so raw output has predictable
artefacts: isolated tooth islands sitting inside gingiva, ragged boundaries,
small gingiva gaps inside teeth. `tools/mesh_morphology.py` cleans this up
using morphological operations on the vertex adjacency graph.

Defaults (enabled via `scripts/visualize.py` unless you pass `--no-postprocess`):

- **Opening** on teeth, 2 iters — removes small isolated tooth islands
- **Closing** on teeth, 2 iters — fills small gingiva gaps inside teeth
- **Gingiva erosion**, 1 iter — corrects slight over-prediction on the border
- **Connected components filter** — drops any region smaller than 500 vertices
- **Boundary smoothing**, 10 iters of graph diffusion

Optional and off by default:

- `--majority-vote N` — trims gingiva peninsulas
- `--open-gingiva N` — removes thin gingiva fingers
- `--reconstruct N` — morphological reconstruction (aggressive, can eat real features)

## Workflow

All commands are run from the project root with the venv active.

```bash
venv\Scripts\activate
```

### 1. Generate training data

Reads raw `.obj` + `.json` pairs from `data/`, projects patches, writes the
three balanced splits to `ml_outputs/training_data/`.

```bash
python scripts/generate_data.py
```

Takes roughly 2–4 hours for 400 scans on an RTX 3070. Key settings in
`config.yaml`:

| Key | Default | Meaning |
|---|---|---|
| `data_generation.scans_for_training` | 400 | Number of scans to use (of 1,850) |
| `data_generation.samples_per_scan` | 500 | Patches sampled per scan |
| `data_generation.boundary_weight` | 0.333 | Fraction drawn from boundary region |
| `data_generation.boundary_radius` | 5.0 | mm radius that counts as "near boundary" |

### 2. Train the model

```bash
python src/train.py
```

Best checkpoint is saved to `ml_outputs/models/teeth_classifier.keras`, with
per-epoch snapshots in `ml_outputs/models/checkpoints/`. Expect 8–12 hours on
an RTX 3070.

Settings in `config.yaml` under `training:` (epochs, batch size, learning rate,
early stopping, etc.).

### 3. Continue training (optional)

If validation accuracy plateaus, resume with a lower learning rate:

```bash
python scripts/continue_training.py --epochs 30 --lr 0.00005
```

### 4. Evaluate on the test split

```bash
python src/evaluate.py
```

Writes accuracy, precision, recall, F1, ROC-AUC, confusion matrix and
per-patient breakdown to `ml_outputs/results/`.

### 5. Visualise a prediction

Runs inference on a single scan, applies post-processing, writes a coloured
`.obj` and a side-by-side comparison PNG.

```bash
python scripts/visualize.py                       # first scan found
python scripts/visualize.py --scan O52P1SZT       # specific scan
python scripts/visualize.py --no-postprocess      # raw model output
python scripts/visualize.py --fast                # sample 1/25 vertices
```

Output lands in `ml_outputs/results/`:

- `prediction_mesh_<scan>.obj` — coloured mesh (ivory = tooth, pink = gingiva)
- `prediction_data_<scan>.json` — per-vertex predictions and confidences
- `prediction_viz_<scan>.png` — 3D scatter plot

### 6. Run batch inference

```bash
python src/predict.py --obj data/<...>.obj --output exports/predictions/
```

Writes a `<scan>_predictions.json` with the vertex labels in the same format
as the dataset's ground-truth JSONs.

## Configuration

Every tunable setting lives in `config.yaml`:

- `paths` — where data, models, logs and results go
- `data_generation` — patch size, sampling strategy, train/val/test split
- `model` — architecture (filter counts, dropout rates, activations)
- `training` — epochs, batch size, optimizer, callbacks, mixed precision
- `evaluation` — threshold, metrics, plots
- `inference` — batch size, JSON output format
- `augmentation` — currently disabled (slowed training more than it helped)

## Known deviations from the brief

These were differences made due to hardware limitations/data limitations.

1. **Geometric channels instead of texture projection.** The brief specifies
   texture-based patches. The 3DTeethSeg dataset has no texture, so the
   patches encode depth / shading / curvature instead. The model still learns
   a useful representation because those three channels cover the same
   "what does the local surface look like" question.
2. **No semi-automatic annotation tool.** The brief described a click-each-tooth
   + auto-polygon + manual-correction tool for generating training labels.
   We used the pre-annotated 3DTeethSeg public dataset instead, which meant
   no annotation tool needed to be built.
